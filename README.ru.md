# LC Checker

**Краткое описание:** LC Checker — инструмент предварительной проверки для экспортёров. Он загружает аккредитив MT700 и отгрузочные документы, извлекает ключевые значения и проверяет их по 15 детерминированным правилам до представления в банк. Он не гарантирует окончательное решение банка.

LC Checker помогает сравнить аккредитив (MT700) с отгрузочными документами до представления их в банк.
Инструмент извлекает значения из документов и по 15 фиксированным правилам показывает несоответствия.
Он не заменяет окончательное решение банка.

## Что делает инструмент?

1. **Загрузка документов** — загрузите аккредитив, коммерческий инвойс, упаковочный лист, коносамент и страховой сертификат.
2. **Извлечение значений** — значения читаются из текстовых файлов и текстового слоя PDF. Аккредитив имеет фиксированный формат и разбирается кодом; остальные документы извлекаются через OpenAI-совместимый LLM API и затем повторно проверяются кодом. По умолчанию используется DeepSeek.
3. **Сверка по правилам** — даты, суммы, количество, вес, число мест, порты, названия и наличие документов сравниваются по фиксированным правилам. Все сравнения выполняются обычным кодом.

## Локальный запуск

### 1. База данных

```bash
docker compose up -d
```

Запускается контейнер PostgreSQL 16 `lc-postgres`.

### 2. API

```bash
cd apps/api
npm install
```

Создайте файл `apps/api/.env` и добавьте в него значения ниже.

```dotenv
DATABASE_URL="postgresql://lcuser:lcpass@localhost:5432/lcchecker?schema=public"

# Подходит любой OpenAI-совместимый API. По умолчанию: DeepSeek.
LLM_API_KEY=your-api-key
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

Старые имена `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` по-прежнему работают как резервный вариант. Также можно использовать OpenAI, OpenRouter, Qwen-совместимые эндпоинты и локальный прокси LiteLLM. Примеры адресов находятся в `apps/api/.env.example`.

Примените схему базы данных и запустите API.

```bash
npx prisma migrate deploy
npm run start:dev
```

API работает по адресу `http://localhost:3000`. Проверка состояния: `GET /health`.

### 3. Веб-приложение

```bash
cd apps/web
npm install
npm run dev
```

Веб-приложение работает по адресу `http://localhost:5173`.

| Назначение | Адрес |
| --- | --- |
| PostgreSQL | localhost:5432 |
| Проверка состояния API | http://localhost:3000/health |
| Веб-приложение | http://localhost:5173 |

## 15 правил проверки

| № | Правило | Что проверяется | Основание UCP 600 (справочно) |
| --- | --- | --- | --- |
| 1 | Крайняя дата отгрузки | Дата погрузки на борт в коносаменте не должна быть позже крайней даты отгрузки по аккредитиву. | Ст. 20(a)(ii), аккредитив :44C |
| 2 | Срок представления (21 день) | С даты погрузки на борт до даты представления должно пройти не более 21 дня. | Ст. 14(c) |
| 3 | Срок действия аккредитива | Дата представления не должна быть позже даты истечения срока действия аккредитива. | Ст. 6(d)(i) |
| 4 | Дата страхования | Дата выдачи страхового документа не должна быть позже даты отгрузки. | Ст. 28(e) |
| 5 | Лимит суммы инвойса | Сумма инвойса не должна превышать сумму аккредитива с учётом допуска, а валюта должна совпадать. | Ст. 18(b), аккредитив :32B/:39A |
| 6 | Совпадение веса брутто | Вес брутто в упаковочном листе и коносаменте должен совпадать. | Ст. 14(d) |
| 7 | Совпадение количества | Общее количество в коммерческом инвойсе и упаковочном листе должно совпадать. | Ст. 14(d) |
| 8 | Совпадение числа мест | Число мест (коробок) в упаковочном листе и коносаменте должно совпадать. | Ст. 14(d) |
| 9 | Соответствие описания товара | Описание товара в инвойсе должно соответствовать описанию товара в аккредитиве. | Ст. 18(c) |
| 10 | Совпадение портов | Порты погрузки и выгрузки в коносаменте должны совпадать с портами аккредитива. | Ст. 14(d), аккредитив :44E/:44F |
| 11 | Совпадение грузополучателя | Грузополучатель в коносаменте должен совпадать с приказодателем аккредитива. | Ст. 14(d), аккредитив :50 |
| 12 | Совпадение уведомляемой стороны | Уведомляемая сторона в коносаменте должна совпадать с приказодателем аккредитива. | Ст. 14(d), аккредитив :50 |
| 13 | Наличие требуемых документов | Все виды документов, требуемые аккредитивом, должны быть загружены. | Ст. 14(a), Ст. 14(b) |
| 14 | Отметка о погрузке на борт | В коносаменте должна быть отметка о погрузке на борт. | Ст. 20(a)(ii) |
| 15 | Индоссамент (не проверяется в этой версии) | Наличие индоссамента на оборотном коносаменте в этой версии не проверяется. | Ст. 14(a), практика индоссирования |

| A | Корректные документы | 0 несоответствий |

| C | Документы с 6 внесёнными ошибками | Несоответствия по правилам 4, 5, 7, 10, 13, 14 |

- Найдены все 12 внесённых ошибок. (**12 / 12**)

- Это проверяется модульными тестами API и e2e-тестом оценки.

## Ограничения

- **Поддерживаются только PDF с текстовым слоем и текстовые файлы.** Сканированные бумажные документы не читаются. OCR запланирован для v2.
- **15 правил — это часть практики UCP 600.** ISBP (Международная стандартная банковская практика) не включён.
- **Правило 15 (индоссамент) в этой версии не проверяется.**
- **Сертификат происхождения в этой версии загрузить нельзя.** Если аккредитив требует сертификат происхождения, правило 13 покажет его как отсутствующий документ.
- **Качество извлечения проверено только на DeepSeek; другие модели не проверялись.**
- **Интерфейс пока только на корейском языке.** Английский интерфейс планируется в v2.
- **Этот инструмент предназначен для предварительной проверки.** Окончательную проверку документов и решение о платеже принимает банк. Такое же уведомление добавлено в последнюю строку отчёта.
