# LC Checker

**English summary:** LC Checker is a pre-check tool for exporters. It uploads an MT700 letter of credit and shipping documents, extracts the key values, and checks them against 15 deterministic rules before bank presentation. It does not guarantee the bank's final decision.

신용장(MT700)과 선적 서류를 은행에 내기 전에 미리 대조하는 도구입니다.
서류에서 값을 뽑고, 정해진 15개 규칙으로 불일치를 찾아 보여 줍니다.
은행의 최종 판정을 대신하지는 않습니다.

## 무엇을 하나요?

1. **서류 올리기** — 신용장, 상업송장, 포장명세서, 선하증권, 보험증서를 올립니다.
2. **값 뽑기** — 텍스트 파일과 PDF의 글자 층에서 값을 읽습니다. 형식이 일정한 신용장은 코드로, 나머지 서류는 OpenAI 호환 LLM API로 값을 뽑고 코드로 다시 검증합니다. 기본 제공자는 DeepSeek입니다.
3. **규칙 대조** — 날짜, 금액, 수량, 중량, 상자 수, 항구, 이름, 서류 구비 여부를 정해진 규칙으로 비교합니다. 비교 자체는 모두 일반 코드로 실행됩니다.

## 로컬 실행 방법

### 1. 데이터베이스

```bash
docker compose up -d
```

PostgreSQL 16 컨테이너 `lc-postgres`가 실행됩니다.

### 2. API

```bash
cd apps/api
npm install
```

`apps/api/.env` 파일을 만들고 아래 값을 넣습니다.

```dotenv
DATABASE_URL="postgresql://lcuser:lcpass@localhost:5432/lcchecker?schema=public"

# 어떤 OpenAI 호환 API든 사용할 수 있습니다. 기본값은 DeepSeek입니다.
LLM_API_KEY=your-api-key
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

기존 `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` 이름도 fallback으로 계속 동작합니다. OpenAI, OpenRouter, Qwen 호환 엔드포인트, 로컬 LiteLLM 프록시도 사용할 수 있습니다. 주소 예시는 `apps/api/.env.example`에 있습니다.

데이터베이스 스키마를 적용하고 API를 실행합니다.

```bash
npx prisma migrate deploy
npm run start:dev
```

API는 `http://localhost:3000`에서 실행됩니다. 상태 확인은 `GET /health`입니다.

### 3. 웹 앱

```bash
cd apps/web
npm install
npm run dev
```

웹 앱은 `http://localhost:5173`에서 실행됩니다.

| 대상 | 주소 |
| --- | --- |
| PostgreSQL | localhost:5432 |
| API 상태 확인 | http://localhost:3000/health |
| 웹 앱 | http://localhost:5173 |

## 검사 규칙 15개

| 번호 | 규칙 | 내용 | UCP 600 근거(참고) |
| --- | --- | --- | --- |
| 1 | 선적 마감일 | 선하증권의 본선적재일이 신용장의 최종 선적일을 넘지 않아야 합니다. | Art. 20(a)(ii), 신용장 :44C |
| 2 | 제시 기한 (21일) | 본선적재일부터 제시일까지 21일을 넘지 않아야 합니다. | Art. 14(c) |
| 3 | 신용장 만료일 | 제시일이 신용장 만료일을 넘지 않아야 합니다. | Art. 6(d)(i) |
| 4 | 보험 날짜 | 보험 발행일이 선적일보다 늦지 않아야 합니다. | Art. 28(e) |
| 5 | 송장 금액 한도 | 송장 금액이 신용장 금액과 허용 오차 범위를 넘지 않고, 통화가 같아야 합니다. | Art. 18(b), 신용장 :32B/:39A |
| 6 | 총중량 일치 | 포장명세서와 선하증권의 총중량이 같아야 합니다. | Art. 14(d) |
| 7 | 수량 일치 | 상업송장과 포장명세서의 총수량이 같아야 합니다. | Art. 14(d) |
| 8 | 상자 수 일치 | 포장명세서와 선하증권의 상자 수가 같아야 합니다. | Art. 14(d) |
| 9 | 물품 설명 대응 | 송장의 물품 설명이 신용장의 물품 설명과 대응해야 합니다. | Art. 18(c) |
| 10 | 항구 일치 | 선하증권의 선적항과 도착항이 신용장의 항구와 맞아야 합니다. | Art. 14(d), 신용장 :44E/:44F |
| 11 | 수하인 일치 | 선하증권의 수하인이 신용장 신청인과 같아야 합니다. | Art. 14(d), 신용장 :50 |
| 12 | 통지처 일치 | 선하증권의 통지처가 신용장 신청인과 같아야 합니다. | Art. 14(d), 신용장 :50 |
| 13 | 요구 서류 구비 | 신용장이 요구한 종류의 서류가 모두 올라와 있어야 합니다. | Art. 14(a), Art. 14(b) |
| 14 | 본선적재 표기 | 선하증권에 본선적재 표기가 있어야 합니다. | Art. 20(a)(ii) |
| 15 | 배서 (이번 버전 검사 제외) | 유통 선하증권의 배서 여부는 이번 버전에서 검사하지 않습니다. | Art. 14(a), 배서 관행 |

## 샘플 점수

`samples/` 폴더의 세 세트로 검사 엔진을 검증했습니다.

| 세트 | 내용 | 결과 |
| --- | --- | --- |
| A | 정상 서류 | 불일치 0개 |
| B | 6개 오류를 심은 서류 | 규칙 1, 2, 6, 8, 9, 12에서 불일치 |
| C | 6개 오류를 심은 서류 | 규칙 4, 5, 7, 10, 13, 14에서 불일치 |

- 심은 오류 12개를 모두 찾았습니다. (**12 / 12**)
- "틀린 것처럼 보이지만 정상"인 함정 2개에서는 거짓 불일치가 나오지 않았습니다.
- API 단위 테스트와 e2e 점수 테스트로 검증합니다.

## 한계

- **글자 층이 있는 PDF와 텍스트 파일만 지원합니다.** 스캔한 종이 서류는 읽지 못합니다. OCR은 v2 범위입니다.
- **15개 규칙은 UCP 600 실무의 일부입니다.** ISBP(국제표준은행관행)는 포함하지 않았습니다.
- **규칙 15(배서)는 이번 버전에서 검사하지 않습니다.**
- **원산지증명서는 이번 버전에서 올릴 수 없습니다.** 신용장이 원산지증명서를 요구하면 규칙 13에서 빠진 서류로 표시됩니다.
- **값 추출 품질은 DeepSeek로만 검증했습니다.** 다른 모델은 아직 검증하지 않았습니다.
- **화면은 한국어, 영어, 러시아어를 지원합니다.** 서버가 저장한 검사 결과 메시지와 검사 못한 이유는 아직 번역하지 않았고, 내려받는 보고서는 한국어로 유지됩니다.
- **이 도구는 미리 점검 도구입니다.** 최종 서류 심사와 지급 판정은 은행이 합니다. 보고서 마지막 줄에도 같은 안내를 넣었습니다.
